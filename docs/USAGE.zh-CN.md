# MediaDock 0.1.0 使用教程

MediaDock 是基于 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 的非官方 macOS
原生前端。当前版本只发布源代码，不提供现成的 `.app` 或 `.dmg`。

请只下载你拥有版权、已经获得授权保存，或平台明确允许保存的内容。MediaDock
不会绕过 DRM、付费墙、账号限制或人机验证。

## 1. 安装前准备

需要：

- Apple Silicon Mac；
- macOS 14 或更高版本；
- Swift 6 Command Line Tools；
- Homebrew。

如果还没有 Command Line Tools，可在终端执行：

```sh
xcode-select --install
```

Homebrew 可从 <https://brew.sh/> 获取。安装 Homebrew 后，安装运行依赖：

```sh
brew install ffmpeg aria2 node
```

各工具的作用：

- `yt-dlp`：解析链接和下载媒体，由 MediaDock 的构建脚本自动下载；
- `ffmpeg` / `ffprobe`：合并分开的视频和音频流；
- `aria2`：在视频源支持时启用多连接下载；
- `node`：为部分需要 JavaScript 挑战处理功能的站点提供运行环境。

## 2. 安装 MediaDock

在 GitHub 页面选择 **Code → Download ZIP**，或克隆源码。进入项目目录后执行：

```sh
./scripts/fetch-core.sh
./scripts/build-app.sh
open build/MediaDock.app
```

`fetch-core.sh` 会下载固定版本的官方 `yt-dlp_macos` 并校验 SHA-256。
`build-app.sh` 会在 `build/MediaDock.app` 生成本地开发版 App。

构建不会复制项目 `Vendor/` 中的 FFmpeg、ffprobe 或 aria2c。请使用 Homebrew
安装这些依赖，不要随意把来源不明的二进制文件放进公开版本。

## 3. 检查下载核心

第一次打开 App 后，查看左侧底部的状态：

- 显示“下载核心已就绪”：`yt-dlp` 已找到；
- 显示“下载核心未就绪”：进入“设置 → 媒体核心”，查看缺少的项目。

“媒体核心”区域还会分别显示 `ffmpeg`、`node` 和 `aria2` 的检测结果。
如果刚在终端安装依赖，点击“重新检查”。

## 4. 下载单个视频

1. 打开左侧的“下载”页面。
2. 确认输入模式为“单个”。
3. 粘贴视频页面链接，或点击“粘贴”读取剪贴板。
4. 点击“解析”，等待缩略图、标题、时长和可用画质出现。
5. 选择画质：
   - “最佳画质”：自动选择可用的最高组合；
   - “1080p”：优先选择不超过 1080p 的清晰度；
   - “仅音频”：导出为 M4A 音频。
6. 如需更换保存位置，点击“更改”。
7. 点击“加入下载队列”。

任务会自动出现在“下载队列”中并开始处理。

## 5. 批量下载

1. 在“下载”页面把输入模式切换为“批量”。
2. 每行粘贴一个视频链接。
3. 点击“批量解析”。一次最多处理 50 个链接。
4. 检查批量预览：
   - 绿色勾选表示可以下载；
   - 解析失败的项目可以单独重试；
   - 重复视频会提示并跳过，不会重复加入队列。
5. 选择统一画质。批量任务使用同一个画质预设。
6. 点击“全部加入队列（数量）”。

也可以把包含多个链接的文本拖入输入区域。失败的项目不会阻止后续链接解析。

## 6. 管理下载队列

左侧“队列”显示尚未完成的任务。每个任务可以看到：

- 当前进度百分比；
- 实时速度和预计剩余时间；
- 当前处理步骤或错误信息；
- 暂停、继续和取消按钮。

暂停不会删除已经下载的部分。恢复时会尽量从现有进度继续。网络中断或任务失败后，
可以进入“历史”页面点击重新下载。

## 7. 下载历史

“历史”页面保存已完成、失败和已取消的任务。你可以：

- 打开已经下载的文件；
- 在 Finder 中显示文件；
- 重新下载失败或已取消的任务；
- 删除一条历史记录；
- 清除全部历史记录。

删除历史记录不会删除磁盘上的视频文件。

## 8. 调整设置

在“设置”页面可以配置：

- **保存位置**：默认是“影片/MediaDock”；
- **默认画质**：解析新链接时自动选择的预设；
- **同时下载**：1–4 个任务并行，建议保持 1–2 个；
- **多连接下载**：视频源支持分段时使用 aria2；
- **下载连接数**：2–16 路，通常 4–8 路较均衡；
- **完成后显示文件**：下载完成后在 Finder 中显示；
- **完成提示音**：任务完成后播放声音。

连接数过高可能触发站点限流，也可能让实际速度下降。若下载变慢，建议先降低到
4–8 路。服务器不支持分段下载时，MediaDock 会自动回退到兼容模式。

## 9. 使用 Chrome 或 Edge 登录状态

遇到“需要登录”“登录以确认”“这不是机器人”等提示时，可让 yt-dlp 使用你浏览器
中已有的登录状态。请先在浏览器中正常登录对应平台。

1. 打开“设置 → 平台登录”。
2. 选择 Chrome 或 Edge。
3. 点击“授权并同步”。
4. Chrome 通常选择：

   ```text
   ~/Library/Application Support/Google/Chrome
   ```

5. Edge 通常选择：

   ```text
   ~/Library/Application Support/Microsoft Edge
   ```

6. 在系统文件选择器中授权对应浏览器数据文件夹。
7. 如果 macOS 请求访问“Chrome Safe Storage”或“Microsoft Edge Safe Storage”，
   只有在你确认继续使用时才授权。

授权后，MediaDock 会在本机复制一份最新的 Cookies 快照，用于解析和下载。
Cookies 不会上传，也不能提交到 Git。特定站点仍可能因账号权限、地区限制、设备验证
或平台策略而拒绝访问。

## 10. 常见问题

### 下载核心未就绪

重新执行：

```sh
./scripts/fetch-core.sh
./scripts/build-app.sh
```

然后打开“设置 → 媒体核心”，点击“重新检查”。

### 高清下载失败或没有声音

安装 FFmpeg：

```sh
brew install ffmpeg
```

高清视频通常将画面和声音拆成两个流，需要 FFmpeg 合并。

### 多连接下载不可用

安装 aria2：

```sh
brew install aria2
```

如果站点本身不支持 HTTP Range，多连接会关闭并自动使用兼容下载。

### YouTube 部分格式不可用

安装 Node.js，并在设置中确认 `node` 已被识别：

```sh
brew install node
```

### 提示需要登录或视频不可用

先确认链接在浏览器中可以正常打开。需要账号权限时，可以配置 Chrome 或 Edge
登录状态；MediaDock 不支持绕过 DRM、付费墙或人机验证。

### 网络中断或下载很慢

网络中断后可在“历史”中重新下载。速度受视频源、网络运营商和连接数影响；
适当降低连接数有时反而更稳定。

### 解析失败

确认链接来自 yt-dlp 支持的视频页面，而不是播放器内部的临时链接。站点结构变化后，
可能需要更新 `scripts/fetch-core.sh` 中固定的 yt-dlp 版本。

## 11. 隐私与文件位置

解析、Cookies、历史记录和媒体都保存在本机。MediaDock 没有账号服务器、遥测或云同步。
下载历史默认保存在 App 的本地状态中；已完成的媒体文件保存在设置指定的下载目录。

不要公开分享 Cookies、密码、验证码、私密视频链接、Keychain 数据或完整的用户目录
诊断日志。
